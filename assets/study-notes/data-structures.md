## 1. 시간 복잡도와 공간 복잡도

### 면접 답변

> 시간 복잡도는 입력 크기가 증가할 때 알고리즘의 연산량이 증가하는 정도이고, 공간 복잡도는 추가로 필요한 메모리가 증가하는 정도입니다. 일반적으로 상수와 낮은 차수 항을 제거한 Big-O 표기법으로 증가율의 상한을 표현합니다.

| 복잡도 | 대표 사례 | 입력이 커졌을 때 |
|---|---|---|
| `O(1)` | 배열 인덱스 접근, 해시 테이블 평균 조회 | 입력 크기와 무관한 일정한 연산 |
| `O(log n)` | 균형 BST 탐색, 힙 삽입·삭제 | 입력이 배로 늘어도 연산은 조금 증가 |
| `O(n)` | 선형 탐색, 연결 리스트 순회 | 입력과 비례 |
| `O(n log n)` | 병합 정렬, 힙 정렬 | 효율적인 비교 정렬의 대표 범위 |
| `O(n²)` | 이중 반복문, 단순한 모든 쌍 비교 | 입력이 커지면 빠르게 증가 |

### 평균, 최악, 분할 상환

- **평균 시간 복잡도**: 가능한 입력 분포를 가정한 평균 비용입니다.
- **최악 시간 복잡도**: 가장 불리한 입력에서의 비용입니다.
- **분할 상환 시간 복잡도**: 여러 연산의 전체 비용을 연산 횟수로 나눈 보장입니다.

동적 배열의 append는 대부분 `O(1)`이지만 가끔 resize로 `O(n)`이 듭니다. 용량을 배수로 증가시키면 연속된 `n`번의 append 전체가 `O(n)`이므로 append 한 번의 분할 상환 비용은 `O(1)`입니다.

## 2. 배열과 동적 배열

### 배열이란?

> 배열은 같은 크기의 원소를 메모리의 연속된 공간에 저장하는 자료구조입니다. 첫 원소의 주소와 원소 크기를 이용해 임의의 인덱스 주소를 계산할 수 있어 random access가 `O(1)`입니다.

![배열과 연결 리스트의 메모리 구조](./static/images/study/array-linked-list.svg)

### 배열의 주요 연산

| 연산 | 시간 복잡도 | 이유 |
|---|---:|---|
| 인덱스 조회 | `O(1)` | `base + index × element_size`로 주소 계산 |
| 인덱스 값 수정 | `O(1)` | 위치를 알고 있으면 바로 덮어씀 |
| 값 탐색 | `O(n)` | 정렬 등 추가 조건이 없으면 순차 비교 |
| 중간 삽입·삭제 | `O(n)` | 뒤쪽 원소를 이동해야 함 |
| 마지막 삽입·삭제 | 고정 배열에서는 조건부 `O(1)` | 남은 용량이 있어야 함 |

> 배열이 항상 컴파일 시점에 Stack에 할당되는 것은 아닙니다. 언어와 선언 방식에 따라 Stack, Heap, 정적 영역 등에 놓일 수 있습니다. 배열의 본질은 **연속된 메모리 배치와 고정된 길이**입니다.

### 배열의 장단점

장점:

- 인덱스 접근이 빠릅니다.
- 연속된 메모리 덕분에 CPU cache locality가 좋습니다.
- 포인터를 원소마다 저장하지 않아 메모리 부가 비용이 작습니다.

단점:

- 고정 배열은 크기를 나중에 바꾸기 어렵습니다.
- 중간 삽입·삭제에는 원소 이동이 필요합니다.
- 큰 연속 공간을 확보해야 할 수 있습니다.

### 동적 배열

> 동적 배열은 내부적으로 고정 배열을 사용하지만 용량이 부족해지면 더 큰 배열을 할당하고 기존 원소를 복사하여 논리적인 크기를 늘리는 자료구조입니다.

```text
size = 4, capacity = 4
[A][B][C][D]

append E → 더 큰 배열 할당
[A][B][C][D][E][ ][ ][ ]
 size = 5, capacity = 8
```

- `size`: 실제 저장된 원소 수
- `capacity`: 재할당 없이 저장 가능한 원소 수
- append: 평균이 아니라 **분할 상환 `O(1)`**
- resize가 발생한 단일 append: `O(n)`

Python `list`, Java `ArrayList`, C++ `vector`가 대표적인 동적 배열입니다. 성장 배율은 구현마다 다르며 반드시 정확히 2배인 것은 아닙니다.

## 3. 연결 리스트

### 면접 답변

> 연결 리스트는 데이터와 다음 노드의 참조를 가진 노드들을 연결한 자료구조입니다. 노드들은 메모리에 연속해서 놓일 필요가 없고 포인터로 논리적인 순서를 표현합니다.

### 종류

| 종류 | 노드가 가진 참조 | 특징 |
|---|---|---|
| 단일 연결 리스트 | `next` | 한 방향 순회 |
| 이중 연결 리스트 | `prev`, `next` | 양방향 순회, 노드 삭제가 편리 |
| 원형 연결 리스트 | 마지막 노드가 처음을 가리킴 | 순환 작업 표현에 유용 |

### 연산 복잡도

| 연산 | 시간 복잡도 |
|---|---:|
| 인덱스 조회 | `O(n)` |
| 값 탐색 | `O(n)` |
| 머리 삽입·삭제 | `O(1)` |
| 알고 있는 노드 뒤 삽입 | `O(1)` |
| 알고 있는 이중 연결 리스트 노드 삭제 | `O(1)` |
| 위치 탐색 후 삽입·삭제 | 탐색을 포함하면 `O(n)` |

“연결 리스트의 삽입과 삭제는 `O(1)`”이라는 답에는 **대상 노드나 이전 노드를 이미 알고 있을 때**라는 조건이 필요합니다.

### 배열과 연결 리스트 비교

| 기준 | 배열·동적 배열 | 연결 리스트 |
|---|---|---|
| 메모리 | 연속적 | 비연속적 |
| 인덱스 접근 | `O(1)` | `O(n)` |
| 중간 삽입·삭제 | 원소 이동 `O(n)` | 위치를 알면 링크 변경 `O(1)` |
| cache locality | 좋음 | 상대적으로 나쁨 |
| 원소별 부가 메모리 | 작음 | 포인터 저장 필요 |
| 크기 증가 | resize가 필요할 수 있음 | 노드 단위 할당 |

실무에서는 연결 리스트의 이론적인 삽입 이점만 볼 것이 아니라 탐색 비용, 포인터 부가 메모리, cache miss, 메모리 할당 비용까지 함께 고려해야 합니다.

## 4. 스택, 큐, 덱

### 스택

> 스택은 가장 나중에 넣은 원소를 먼저 꺼내는 LIFO 자료구조입니다. `push`, `pop`, `top`은 일반적으로 `O(1)`입니다.

활용:

- 함수 호출 스택
- 괄호 유효성 검사
- 실행 취소
- DFS
- 수식 계산과 구문 분석

### 큐

> 큐는 먼저 넣은 원소를 먼저 꺼내는 FIFO 자료구조입니다. `enqueue`와 `dequeue`를 일반적으로 `O(1)`에 수행합니다.

활용:

- BFS
- 작업 대기열
- 메시지 버퍼
- 프린터·CPU 작업 관리

배열 기반 큐에서 앞 원소를 제거할 때마다 모든 원소를 이동하면 `O(n)`입니다. 이를 피하려고 `front`와 `rear` 인덱스를 이동시키는 **원형 큐**를 사용합니다.

### 덱

덱(Deque)은 양쪽 끝에서 삽입과 삭제가 가능한 자료구조입니다. Queue와 Stack 동작을 모두 표현할 수 있고 슬라이딩 윈도 최댓값, 0-1 BFS 등에 활용합니다.

### 두 개의 Stack으로 Queue 구현

```text
enqueue(x): input_stack에 push

dequeue():
  output_stack이 비었다면
    input_stack의 모든 원소를 output_stack으로 이동
  output_stack에서 pop
```

한 원소는 input stack에 한 번 들어가고 output stack으로 한 번 이동한 뒤 한 번 나옵니다. 따라서 한 번의 dequeue가 최악 `O(n)`이어도 여러 연산에 대한 분할 상환 비용은 `O(1)`입니다.

## 5. 힙과 우선순위 큐

### 우선순위 큐

일반 Queue는 먼저 들어온 원소가 먼저 나오지만, 우선순위 큐는 우선순위가 가장 높은 원소가 먼저 나옵니다. 우선순위 큐는 추상 자료형이고, **Binary Heap**은 이를 구현하는 대표 자료구조입니다.

### Binary Heap

> Binary Heap은 완전 이진 트리의 모양 조건과 부모·자식 사이의 heap property를 만족하는 자료구조입니다.

![배열로 표현한 최소 힙과 이진 탐색 트리](./static/images/study/heap-bst.svg)

- Min Heap: 부모 값이 자식 값보다 작거나 같습니다.
- Max Heap: 부모 값이 자식 값보다 크거나 같습니다.
- 형제 사이의 대소 관계는 보장하지 않습니다.
- 루트에는 최솟값 또는 최댓값이 있습니다.

### 배열로 구현하는 이유

완전 이진 트리는 빈 공간 없이 레벨 순서로 채워지므로 배열 인덱스로 관계를 계산할 수 있습니다.

0번 인덱스를 사용하는 경우:

```text
left(i)   = 2i + 1
right(i)  = 2i + 2
parent(i) = (i - 1) // 2
```

| 연산 | 복잡도 |
|---|---:|
| 최솟값·최댓값 확인 | `O(1)` |
| 삽입 | `O(log n)` |
| 루트 삭제 | `O(log n)` |
| 임의 값 탐색 | `O(n)` |
| n개 원소 heapify | `O(n)` |

삽입은 마지막에 추가한 뒤 위로 올리는 sift-up, 루트 삭제는 마지막 원소를 루트로 옮긴 뒤 아래로 내리는 sift-down을 수행합니다.

## 6. 트리와 이진 탐색 트리

### 기본 용어

- Root: 부모가 없는 최상위 노드
- Edge: 노드 사이의 연결
- Leaf: 자식이 없는 노드
- Depth: Root부터 해당 노드까지의 간선 수
- Height: 노드에서 가장 깊은 Leaf까지의 간선 수
- Binary Tree: 각 노드의 자식이 최대 두 개인 트리

### 이진 탐색 트리

> BST는 모든 노드에 대해 왼쪽 서브트리 값은 현재 값보다 작고, 오른쪽 서브트리 값은 현재 값보다 큰 순서 조건을 만족하는 이진 트리입니다.

| 연산 | 균형에 가까울 때 | 한쪽으로 치우쳤을 때 |
|---|---:|---:|
| 탐색 | `O(log n)` | `O(n)` |
| 삽입 | `O(log n)` | `O(n)` |
| 삭제 | `O(log n)` | `O(n)` |

정렬된 데이터를 순서대로 삽입하면 트리가 연결 리스트처럼 치우칠 수 있습니다. AVL Tree와 Red-Black Tree는 회전 등을 이용해 높이를 `O(log n)` 범위로 유지하는 self-balancing BST입니다.

### 트리 순회

| 순회 | 순서 | 대표 활용 |
|---|---|---|
| Preorder | Root → Left → Right | 트리 복사, 직렬화 |
| Inorder | Left → Root → Right | BST 값을 정렬된 순서로 방문 |
| Postorder | Left → Right → Root | 하위 결과를 모아 계산, 삭제 |
| Level order | 레벨 단위 BFS | 최단 깊이, 계층 출력 |

### Heap과 BST의 차이

- Heap은 Root의 최솟값·최댓값을 빠르게 꺼내는 데 집중합니다.
- BST는 특정 Key를 탐색하고 정렬된 순회·범위 탐색을 하는 데 적합합니다.
- Heap은 왼쪽·오른쪽 서브트리 전체의 정렬 관계를 보장하지 않습니다.

## 7. 해시 테이블

### 면접 답변

> 해시 테이블은 Key를 Hash Function에 넣어 얻은 Hash 값을 Bucket 위치로 변환하고 Key-Value를 저장하는 자료구조입니다. 충돌이 적고 적절한 Load Factor를 유지하면 검색, 삽입, 삭제의 평균 시간 복잡도가 `O(1)`입니다.

![해시 충돌과 해결 방식](./static/images/study/hash-collision.svg)

### 직접 주소 테이블과의 차이

직접 주소 테이블은 정수 Key `k`를 배열의 `k`번 인덱스에 바로 저장합니다. Key 범위가 매우 크거나 문자열 같은 Key를 쓰면 공간을 낭비하거나 바로 인덱스로 사용할 수 없습니다. 해시 함수는 큰 Key 공간을 제한된 Bucket 공간에 매핑합니다.

### 충돌

서로 다른 Key가 같은 Bucket 위치로 매핑되는 현상입니다. Bucket 수가 유한한 이상 충돌 가능성을 완전히 없앨 수 없으므로 해결 전략이 필요합니다.

#### Separate Chaining

같은 Bucket에 들어온 항목들을 연결 리스트나 트리 같은 별도 구조에 저장합니다.

- 구현이 비교적 단순합니다.
- Load Factor가 1을 넘을 수 있습니다.
- 포인터와 별도 메모리 할당 비용이 생깁니다.

#### Open Addressing

모든 항목을 Hash Table 배열 내부에 저장하고 충돌 시 다른 빈 Slot을 탐사합니다.

- Linear Probing: 일정 간격으로 다음 Slot을 확인
- Quadratic Probing: 제곱 형태로 탐사 폭 증가
- Double Hashing: 두 번째 Hash Function으로 탐사 간격 결정

Linear Probing은 가까운 영역에 항목이 몰리는 primary clustering이 발생할 수 있습니다.

### Load Factor와 Rehash

```text
load factor α = 저장된 원소 수 / bucket 수
```

Load Factor가 커질수록 충돌 가능성과 탐색 길이가 증가합니다. 구현체는 임계값을 넘으면 더 큰 Table을 만들고 모든 Key의 위치를 다시 계산하는 rehash를 수행합니다.

### 좋은 Hash Function

- 같은 Key에 항상 같은 Hash 값을 반환해야 합니다.
- 계산이 충분히 빨라야 합니다.
- 입력 Key를 Bucket 전체에 가깝게 균등 분산해야 합니다.
- 비슷한 Key가 특정 Bucket에 몰리지 않아야 합니다.
- 보안 환경에서는 공격자가 의도적인 충돌을 만들기 어려워야 합니다.

평균 연산은 `O(1)`이지만 모든 Key가 한 Bucket에 모이면 최악 `O(n)`이 될 수 있습니다.

---

## 8. 그래프와 탐색

### 그래프 표현

| 표현 | 공간 | 간선 존재 확인 | 모든 이웃 순회 |
|---|---:|---:|---:|
| 인접 행렬 | `O(V²)` | `O(1)` | `O(V)` |
| 인접 리스트 | `O(V + E)` | 일반적으로 차수에 비례 | `O(degree)` |

간선이 적은 Sparse Graph는 인접 리스트가 효율적이고, 간선이 매우 많은 Dense Graph나 빠른 간선 확인이 필요하면 인접 행렬을 고려합니다.

### BFS와 DFS

| 구분 | BFS | DFS |
|---|---|---|
| 핵심 자료구조 | Queue | Stack 또는 재귀 호출 |
| 방문 방식 | 가까운 정점부터 레벨 단위 | 한 경로를 끝까지 탐색 |
| 시간 복잡도 | `O(V + E)` | `O(V + E)` |
| 대표 활용 | 가중치 없는 최단 거리, 레벨 탐색 | 사이클, 연결 요소, 위상 정렬 |

두 탐색 모두 방문 배열이나 Set을 사용하지 않으면 같은 정점을 반복 방문할 수 있습니다.

---

## 9. 자료구조 선택 기준

| 요구사항 | 우선 고려할 자료구조 |
|---|---|
| 인덱스로 빠르게 접근·순회 | Array, Dynamic Array |
| 이미 찾은 위치에서 잦은 삽입·삭제 | Linked List |
| 최근 항목부터 처리 | Stack |
| 도착 순서대로 처리 | Queue |
| 양쪽 끝 삽입·삭제 | Deque |
| 최솟값·최댓값을 반복 추출 | Heap, Priority Queue |
| 평균적으로 빠른 Key 조회 | Hash Table |
| 정렬 상태와 범위 탐색 | Balanced BST |
| 계층 관계 | Tree |
| 임의의 연결 관계 | Graph |

자료구조를 선택할 때는 Big-O뿐 아니라 데이터 크기, 메모리 부가 비용, cache locality, 정렬 필요성, 최악 성능 보장까지 함께 고려합니다.

## 10. 핵심 용어

| 용어 | 설명 |
|---|---|
| Random Access | 앞 원소를 거치지 않고 인덱스로 특정 위치에 바로 접근하는 방식 |
| Cache Locality | 가까운 시간이나 메모리 위치의 데이터를 다시 사용할 가능성이 높은 성질 |
| Amortized Analysis | 연속된 여러 연산의 총비용으로 연산당 비용을 분석하는 방법 |
| Node | 데이터와 연결 정보를 담는 자료구조의 구성 단위 |
| Complete Binary Tree | 마지막 레벨을 제외한 모든 레벨이 차 있고 마지막은 왼쪽부터 채워진 트리 |
| Load Factor | Hash Table에서 Bucket 수 대비 저장 원소 수의 비율 |
| Collision | 서로 다른 Key가 같은 Hash 위치로 매핑되는 현상 |
| Rehash | Table 크기를 바꾸고 모든 Key의 Bucket 위치를 다시 계산하는 과정 |
| Sparse Graph | 가능한 간선 수에 비해 실제 간선이 적은 그래프 |
| Stable Sort | 값이 같은 원소들의 기존 상대 순서를 유지하는 정렬 |
